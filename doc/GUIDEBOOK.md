## 1. 项目一句话与大图

**一句话**：摄像头拍到的画面，在 FPGA 里实时算出"边缘图"（Canny 算法），
再送给一个仿脑神经元网络（SNN）统计画面活跃度，最后显示出来。
全程不占用 CPU——所有像素级的数学都是硬件电路并行算的。

```
 OV5640 摄像头          FPGA 内部 (XC7Z020)
┌──────────┐  DVP 并口   ┌─────────────────────────────────────────┐
│ 传感器    │────────────▶│ 采集 ─▶ 跨时钟FIFO ─▶ Canny边缘检测流水线 │
│ (SCCB配置)│◀───────────│  ▲SCCB          │                        │
└──────────┘  I2C配置线   │ 50MHz系统时钟    ├─▶ SNN脉冲神经网络       │
                        │                 └─▶ 显示 (VGA时序/LCD)    │
                        └─────────────────────────────────────────┘
```

**Canny 边缘检测是什么**：一张图里"物体轮廓"的像素。算法流程固定五步：
高斯模糊（去噪）→ Scharr 梯度（找亮度变化方向）→ 中值滤波（去孤立噪点）→
非极大值抑制（把粗边变细）→ 双阈值+滞回连接（决定哪些边最终保留）。
每一步都是"卷积窗口"操作——这正是 FPGA 最擅长的：窗口并行展开成加法树，
一个像素一拍。

**SNN 是什么**：Leaky Integrate-and-Fire 神经元的脉冲网络。把 8×8 池化后的
边缘活动当作输入电流，跑 64 个时间步，统计每个神经元的放电次数——
相当于一个超小型的"事件计数大脑"，用来演示 FPGA 也能跑类脑计算。

## 2. FPGA 地基知识

### 2.1 FPGA 到底是什么

CPU 是"固定的电路跑变化的指令"；FPGA 是"你要什么电路，它就变成什么电路"。
你用 Verilog 描述电路，Vivado 把它"编译"（综合）成一片可配置芯片里的
真实连线。**写 Verilog 不是写程序，是在画电路**——这是初学者最大的心魔。
每个 `always @(posedge clk)` 块都是一排真实的触发器，每个 `assign` 都是一
段真实的导线和门。

### 2.2 芯片里的四种积木（XC7Z020 实物参数）

| 积木 | 本芯片有 | 干什么 | 本项目怎么用 |
|---|---|---|---|
| **LUT**（查找表） | 53200 个 | 6 输入任意逻辑函数，万能门 | 算法组合逻辑、比较器、加法器 |
| **FF**（触发器） | 106400 个 | 存 1 比特，时钟沿更新 | 流水线寄存器、状态机、计数器 |
| **BRAM**（块存储） | 140 个 36Kb | 双端口片上 RAM | 滞回连接的两个整帧位图、SNN 权重 |
| **DSP48** | 220 个 | 硬乘加器 | 梯度方向的 12×14 位乘法（只用 4 个） |

还有两个特殊资源：
- **MMCM**（时钟管理）：把输入的 50MHz 晶振"频率合成"成 180MHz 处理时钟
  和 75MHz 显示时钟。本项目用 `MMCME2_BASE` 原语，VCO=1125MHz 再分频。
- **BUFG**（全局时钟缓冲）：让时钟信号以最小偏斜到达全芯片。综合器自动插。

### 2.3 时钟域与 CDC（跨时钟域）——本项目的命脉

摄像头用自己的时钟（PCLK，约 56MHz），处理引擎用 180MHz（clk_proc），
两者**没有倍数关系、相位随机漂移**。一个信号直接跨过去会发生什么？
目的域的触发器可能恰好在数据变化的瞬间采样，进入**亚稳态**——
输出在 0/1 之间抖动一段时间，可能连锁污染整个系统。

**标准解法（本项目全部遵守，写在架构文档里作为铁律）**：
- **单 bit 控制信号** → 两级触发器同步器 `sync_2ff`（`rtl/common/sync_2ff.v`）。
  第一级可能亚稳，但绝大概率在一个周期内稳定，第二级输出就是干净的了。
  代码里 `(* ASYNC_REG = "TRUE" *)` 属性告诉布局器把这两级放得紧紧的。
- **多 bit 数据流** → 异步 FIFO `fifo_async`（`rtl/common/fifo_async.v`）。
  关键技巧是**格雷码指针**：二进制指针每次加一可能翻转 8 个比特
  （0111→1000），跨域时若某几位采到新值某几个采到旧值，指针就"错位"了。
  格雷码每次只翻一个比特，即使采到旧值也只是"保守地认为少了一个数据"，
  永远不会错。写满/读空的判断用同步到本域的对方格雷指针做比较。

### 2.4 流水线——FPGA 性能的灵魂

一个 8 位加法只要 1ns，但"窗口 → 排序网络 → 输出"这种 100 级逻辑的路
径要 15ns，150MHz（周期 6.67ns）下根本跑不完。怎么办？**中间插寄存器**：

```
慢: A ──[15ns组合逻辑]──▶ Z            最高 66MHz
快: A ──[5ns]──▶ r1 ──[5ns]──▶ r2 ──[5ns]──▶ Z   最高 200MHz
```

寄存器不改变**功能**（数据照样从 A 流到 Z），只把总延迟从"一拍很长"变成
"三拍每拍很短"。本项目 5 个算法模块全部流水化，最深的中值滤波拆到 7 级。
**代价**：结果晚几拍出来、每级多几十个 FF——对于每帧 30 万像素的图像流
这点延迟（几十纳秒）完全无所谓。

### 2.5 面积换速度：并行展开

软件算 5×5 卷积是 25 次乘加循环；FPGA 可以**同时放 25 个乘法器一拍出结果**。
本项目的窗口引擎把 25 个像素同时摆在面前（`window_kxk` 的 `w_pix` 是
25 个 8 位信号的总线），高斯核的移位加全部并行展开——这就是
"150MHz × 每拍 1 像素 = 1.8 亿像素/秒"的来源。

## 3. 系统架构与数据流

### 3.1 时钟域全景

```
sys_clk 50MHz (晶振 M19)
  ├─ clk_cfg  = 50MHz 直通        → SCCB 配置、AXI 寄存器堆、软核 FSM
  └─ MMCM ── clk_proc = 180MHz    → Canny 流水线、SNN、FIFO 读侧
           ├ clk_pix  = 75MHz     → VGA 时序发生器
PCLK (摄像头 W17, ~56MHz)          → 像素采集、FIFO 写侧
```

三个域的交界全部走白名单原语：PCLK→proc 走 `fifo_async`（像素数据），
cfg→proc 走"值稳定两拍同步"（阈值类配置），proc→cfg 走握手脉冲展宽。

### 3.2 像素的一生（数据流逐步）

以通道 0 为例，一个像素从光子到边缘判定：

1. **采集**（`ov5640_ctrl`，PCLK 域）：OV5640 输出 DVP 格式——`href` 高
   电平期间每拍一个字节。模块按 RGB565 拆解取 G 通道作灰度，拼出
   `px_v/px_d` 流。帧/行同步用 `vsync`。
2. **跨域**（`fifo_async` 2048×8bit）：PCLK 侧写入，proc 侧读出。
3. **读侧整形**（vision_top 内）：FIFO 空了就停；每行 640 像素读完后
   强制塞 4 拍空隙——这是窗口引擎的"行尾补零"契约（见 4.2）。
4. **Canny 流水线**（`canny_top`，proc 域，7 个子模块串联）：
   高斯 → Scharr → 幅值/方向 → 中值 → NMS → 双阈值 → 滞回。
   每级之间是统一的 `valid/sof/eol/eof + data` 流式接口。
5. **SNN 活动池化**：边缘图按 8×8 分箱累加到 `act_mem[64]`，
   帧结束时自动启动一次 64 时间步推理，脉冲计数可从寄存器读回。
6. **显示**（pix 域）：VGA 时序发生器出同步信号（LCD 适配是 Phase 9 板级内容）。

### 3.3 控制面（配置与状态）

`vexriscv_wrapper`（SOFT_CTRL=1 时是内置 FSM，=0 时接真 VexRiscv CPU 网表）
通过 AXI4-Lite 总线访问 `axi_crossbar_wrap` 寄存器堆：

| 地址 | 寄存器 | 说明 |
|---|---|---|
| 0x000 | ID | 芯片标识（读回验证总线通） |
| 0x004 | MODE | 显示模式（消隐期切换才生效） |
| 0x008/0x00C | TH_HI/TH_LO | Canny 双阈值（600/200 默认） |
| 0x014 | SNN_VTH | 神经元阈值（Q8.16 定点） |
| 0x030+ | SNN_CNT[i] | 每神经元脉冲计数（只读） |

上电流程：SCCB 配置摄像头（约 180ms，寄存器表在 `mem/ov5640_reg_dump.hex`）→
核对 Chip ID → `cfg_done` 置位 → FIFO 复位释放 → 数据开始流动。

## 4. 逐模块精讲

> 每个模块按"干什么 → 怎么实现 → 为什么这样设计 → 怎么验证"讲。
> 文件都在 `rtl/` 下，行数不多，强烈建议对照源码读。

### 4.1 `sync_2ff`（34 行）——最简单也最重要

```verilog
(* ASYNC_REG = "TRUE" *) reg [STAGES-1:0] sync_ff;
always @(posedge clk or negedge rst_n) begin
    if (!rst_n)  for (i=0;i<STAGES;i=i+1) sync_ff[i] <= INIT;
    else begin   sync_ff[0] <= d_in;
                 for (i=1;i<STAGES;i=i+1) sync_ff[i] <= sync_ff[i-1]; end
end
assign q_out = sync_ff[STAGES-1];
```
**为什么**：见 2.3。**注意**：只允许单 bit 过境；拿它同步多 bit 总线是
经典错误——各 bit 到达时间不同，组合出的值谁都没见过。

### 4.2 `window_kxk`（207 行）——被 5 个模块复用的窗口引擎

**干什么**：把串行像素流变成"K×K 窗口并行视图"。输入 `s_valid/s_data`，
输出 `w_pix[行][列]`——9 或 25 个像素**同一拍**摆在总线上，
下游模块想怎么组合就怎么组合。

**怎么实现**（K=5 为例）：
- **行存**：4 个 bank（K-1 行历史），每个 bank 是一行 640 深度的分布式 RAM。
  当前行写进 bank `r%4`，同时读出最老的一行——乒乓轮转。
- **列移位**：每行内部是 5 深移位链 `sr[4:0]`，最新像素进 `sr[4]`。
- **边界补零**：图像边框外的窗口位置强制 0——上/下越界看行号判断，
  左/右越界靠"行尾多移 2 拍零、行首移位链承接上一行行尾的零"。
  这就是上游必须提供"行间 ≥4 空拍"契约的原因：窗口引擎要靠这些
  空拍把行尾的 2 个零推进移位链。

**为什么这样设计**：一个引擎服务 5 个不同尺寸的滤波器（5×5 高斯、
3×3 Scharr、3×3 中值、3×3 NMS、3×3 滞回邻域），参数化 K/DW/IMG_W/IMG_H。
行存用分布式 RAM 而非 BRAM：每行只需 640×8bit，且需要**异步读**
（窗口发射当拍要同时读出 5 个 bank），BRAM 做不到。

**重要教训**：行存必须是"每 bank 一个独立 1D 数组 + generate"。
早期版本写成 2D 数组 `mem[3][640]` 加组合多 bank 遍历，综合器把它
摊平成巨型多路器——**22908 个 LUT**。改成 generate 后同功能只剩 127 个。

### 4.3 `gaussian_5x5`（134 行）——可分离卷积 + 全移位加

高斯核 [1,4,6,4,1]² 有个数学性质：二维卷积可拆成两次一维卷积，
25 次乘法变 10 次加法。而且系数全是 2 的倍数——**乘法全部变成移位加**：

```verilog
// 4*x 等于 x 左移 2 位: {2'b0, x, 2'b00}
t = prow[0] + (prow[1]<<2) + (prow[2]<<2 + prow[2]<<1) + (prow[3]<<2) + prow[4];
```
最后除以 256（右移 8 位）前加 128 做四舍五入：`clamp((acc+128)>>8)`。
4 级流水：行部分积 → 行和 → 垂直部分和 → 总加+舍入。零 DSP、零乘法器。

### 4.4 `scharr_3x3` + `gradient_mag_dir`（114+110 行）

Scharr 核求 x/y 两个方向的梯度（亮度变化率）：
`Gx = [-3 0 3; -10 0 10; -3 0 3]`，Gy 是它的转置。同样全移位加。
输出饱和到 12 位有符号。

`gradient_mag_dir` 算幅值和方向：
- 幅值用 `|Gx|+|Gy|` 近似（代替开方），饱和 12 位；
- 方向量化成 4 档（0°/45°/90°/135°），判据是整数乘法比较：
  `|Gy|*10000 ≤ |Gx|*4142 → 0°`（tan22.5°≈0.4142）。用乘法避免除法，
  且与 golden model 的浮点判据**逐位一致**（边界像素用穷举验证过）。

### 4.5 `median_3x3`（232 行）——19 比较器中值网络

9 个数取中值，朴素排序要 30+ 比较器。数学恒等式：
```
median(9) = median( max(各行min), min(各行max), median(各行median) )
```
3 行各做 sort3（3 比较器），再对三个代表值做一次 sort3——共 19 个。
每个 sort3 再拆成"首拍比较选 lo/hi + 次拍插入第三个数"两级，
整条链 7 级流水，每级只有 1 个 12 位比较器深度，稳定跑 180MHz。

### 4.6 `nms`（72 行）——非极大值抑制

沿梯度方向比较：若中心幅值 < 方向两侧任一邻居，置零（粗边变 1 像素细边）。
方向是 4 档，比较对象是窗口里固定的两个位置——纯组合查表。

### 4.7 `double_threshold` + `hysteresis`（50+266 行）——双阈值与滞回连接

**双阈值**：幅值 > TH_HI（默认600）= 强边缘（一定保留）；
TH_LO~TH_HI = 弱边缘（看邻居）；< TH_LO = 丢弃。每像素 2 bit 分类。

**滞回**（全项目最难的模块）：弱边缘只要 8 邻域内有一格强边缘就升级，
升级可能连锁——像墨水在纸上晕开。实现是**迭代法**：
1. PH_CAPT：整帧分类图写进两个 1bit 位图 BRAM（strong/weak）；
2. PH_PASS：整帧重读一遍，经窗口引擎看 8 邻域，发现可升级就写回 strong，
   置 `changed` 标志；
3. PH_CHECK：本轮有变化且未到 MAX_PASS（64）就再来一轮；
4. PH_OUTPUT：整帧输出 strong 位图。
   典型图像 2~3 轮收敛；病态的"蛇形长线"才需要更多轮。

**BRAM 推断的关键**：两个位图必须写成"单进程、单端口 mux、同步读"模式，
加 `(* ram_style = "block" *)`。VGA 下各占 10 个 BRAM36。
早期异步读版本推断失败，摊成 30 万 LUT 的分布式 RAM，直接把综合器打爆
（内存 10.5GB OOM）——这是本项目最大的一次返工。

### 4.8 `snn_top`（180 行）——脉冲神经网络

16 个 LIF 神经元，64 输入突触。每个时间步：
`v[j] += Σ w[i][j]*act[i] - leak; if (v[j] > vth) { spike; v[j] = 0 }`
电压是 Q8.16 定点（高 8 位整数 + 低 16 位小数），权重存 BRAM
（`mem/cls_64x64.hex` 初始化）。64 步推理只要 427ns@180MHz——
每帧都能跑，几乎免费。单独综合 2357 LUT + 1 RAMB18。

### 4.9 传感器与控制

- `sccb_master`（203 行）：I2C 的简化版（SCCB），100kHz，三态 SDA。
  帧结构 `[ID+W, 寄存器地址, 数据]`，读操作用 repeated-START。
  **坑**：SCCB 没有时钟拉伸，从机 ACK 释放 SDA 必须在 SCL 低电平期间，
  否则被主机误判成 START/STOP。
- `ov5640_ctrl`（278 行）：上电复位→读 Chip ID（0x5640 校验）→
  按表写 ~200 个配置寄存器（分辨率/白平衡/GAMMA）→`cfg_done`。
  DVP 采集域单独复位，`cfg_done` 之前不放开——防止摄像头复位期间
  引脚悬空抖动灌进伪数据。

### 4.10 顶层 `vision_top`（395 行）

所有模块的组装厂。三个要点：
- **多核 generate**：`for (gc=0; gc<NCHAN; gc++)` 每通道一套
  FIFO+读侧+Canny（见第 7 章）；
- **配置跨域**：阈值走"值稳定两拍"，SNN 启动脉冲走"toggle 翻转检测"；
- **仿真旁路**：`sim_s_valid/sim_s_data` 绕过传感器直接注入像素流
  （`SIMPLIFIED_CLK` 宏下单时钟域），让端到端 TB 不用等 180ms 的
  SCCB 配置仿真。

## 5. 验证方法论

### 5.1 黄金模型（Golden Model）——位级精确对比

`scripts/golden_model.py` 用 Python 按同样的数学（同样的补零、同样的
舍入、同样的整数方向判据）算一遍整幅图，输出 `golden_output.hex`。
仿真 TB 把 RTL 输出和它**逐位**对比——不是"差不多"，是 4096/4096
像素每一位都相同才算 PASS。这叫 位精确（bit-exact）验证。

为什么能位精确？因为设计时就把所有"软件里有无数种实现"的细节冻结了：
高斯舍入用 +128 而不是 floor；方向判据用整数乘法等价改写；
中值用 19 比较器网络（穷举验证与 sorted()[4] 恒等）。
**硬件和模型必须共享同一套决策**，位精确才有可能。

### 5.2 测试金字塔

```
                 tb_vision_top / tb_multi     端到端 (整系统, 慢, 抓集成问题)
              ┌──────────────────────────┐
              │ tb_canny ×4图案            │  流水线级 (7模块串联 vs golden)
              ├──────────────────────────┤
              │ tb_hyst/tb_scharr/...     │  单模块 (快, 定位容易)
              ├──────────────────────────┤
              │ tb_axi_stream/tb_window   │  基础设施 (FIFO/窗口引擎)
              └──────────────────────────┘
```
14 个 TB 全部自检查（打印 PASS/FAIL + $finish），一个脚本跑完：
`bash scripts/run_regression.sh`（约 5 分钟）。

### 5.3 流式 TB 的写法要点

**不要依赖固定延迟**。模块流水级数改动后（3 级改 7 级），若 TB 按
"输入后第 N 拍出结果"取数就会全错。正确写法是只认 valid：

```verilog
always @(posedge clk) if (m_valid && out_cnt < N) begin
    if (m_data !== gold[out_cnt]) errors++;
    out_cnt++;
end
```
本项目所有 TB 都是这种"流式对比"，所以流水线从 1 级拆到 7 级，
TB 一行没改照样通过。

### 5.4 四种测试图案的用意

| 图案 | 考什么 |
|---|---|
| edge（几何图形）| 常规路径 |
| edgecase（全边界值：0/127/128/255）| 饱和、舍入进位、比较边界 |
| noise（随机）| 中值网络全排列、方向全分支 |
| flat（全同值）| "什么都不该发生"——防假边 |

## 6. 时序收敛实战

### 6.1 什么叫"时序违例"

综合布线后，Vivado 检查每条"寄存器→寄存器"路径：数据从源触发器出发，
穿过组合逻辑和导线，必须在下一个时钟沿**之前**到达目的触发器。
到不了 = 建立时间违例（WNS 为负）。负 8ns 意味着这条路径要 14.8ns
而时钟只给 6.67ns。

### 6.2 我们的收敛之路（每一步都有数据）

| 版本 | WNS | 瓶颈路径 | 动作 |
|---|---|---|---|
| v1 | -8.154 | 中值排序网络（4 级 sort3 串联 14.8ns）| 拆 3 级流水 |
| v2 | -4.434 | 高斯窗口→输出（11ns 加法树）| 拆 4 级 |
| v3 | -3.880 | Scharr/mag_dir（乘法+比较 10ns）| 各拆 3 级 |
| v4 | -1.457 | mag_dir 乘法单拍太重 | 乘法单独一拍 |
| v5 | -0.267 | 滞回 BRAM→窗口分布式RAM 写口 | 插输入寄存 |
| v6 | **+0.133** | — | **收敛**（后又优化到 +0.321）|

**方法论**：`report_timing -max_paths 10` 看 Source/Destination 定位模块 →
在组合路径中间插寄存器（配套把 valid/sof/eol/eof 也延迟同样级数）→
回归测试确认功能不变 → 重新综合。每轮 30~40 分钟，共 6 轮。

### 6.3 一个必须掌握的细节：valid/数据级数失配

拆流水时最容易犯的错。给 `gradient_mag_dir` 加了一级 abs 寄存后，
数据链变成 3 级，但 valid 链还是 4 级——输出 valid 比数据晚一拍，
TB 采到的全是错位数据（方向判定用的是下一个像素的乘积）。
**症状**：单模块仿真错误率约 6%，且错误集中在方向边界像素。
**修复**：数清楚每条子路径（数据/valid/标志）的寄存器级数，
输出级一次性对齐。详见 `rtl/img_proc/gradient_mag_dir.v` 的注释。

## 7. 多核扩展

### 7.1 NCHAN 机制

`vision_top` 的参数 `NCHAN` 控制 generate 生成几套独立的
`FIFO → 读侧 → canny_top`。通道 0 与真实 DVP 采集并联，
通道 1~N-1 走仿真旁路（未来接更多摄像头）。

```verilog
genvar gc;
generate for (gc = 0; gc < NCHAN; gc = gc + 1) begin : g_chan
    fifo_async #(...) u_cdc (...);
    canny_top  #(...) u_canny (...);
end endgenerate
```

**为什么要多核**：单核 180MHz = 180M 像素/秒，已远超 OV5640 的供给。
但 2K@60 需要 221M、4K@30 需要 249M——单核不够，多核线性叠加。

### 7.2 已验证的配置

| 配置 | 时钟 | 总吞吐 | LUT | BRAM | WNS |
|---|---|---|---|---|---|
| NCHAN=1 | 180MHz | 180M px/s | 7.6% | 14.3% | +0.139ns |
| NCHAN=2 | 180MHz | 360M px/s | 20.8% | 28.9% | +0.039ns |
| NCHAN=4 | 165MHz | 660M px/s | 35.2% | 57.5% | +0.050ns |

4 核跑不了 180MHz 的原因：80 个 BRAM 挤占布线资源，滞回模块的
BRAM 输出路径差 0.67ns。降 9% 时钟换收敛，性价比合理。
（BRAM 数量是核数天花板：每核 20 个，140 个里 80.5% 已是 4 核极限。）

### 7.3 多核验证

`tb_multi`（NCHAN=2）双通道**同时**喂不同图案，各自对比独立 golden——
4096+4096 像素全部位精确，证明通道间零串扰。

## 9. 性能与资源总账

### 9.1 资源（单核 180MHz，布线后实测）

| 资源 | 用量 | 占比 | 大头在哪 |
|---|---|---|---|
| LUT | ~4100 | 7.6% | Canny 2660 + CDC FIFO 524 + 采集 280 |
| FF | 2251 | 2.1% | 流水线寄存器（时序收敛的代价，值得）|
| BRAM36 | 20 | 14.3% | **全部**在滞回的双帧位图（这是核数天花板）|
| DSP | 4 | 1.8% | 方向量化的 3 个乘法 + 采集域 1 个 |

### 9.2 性能

- **单核吞吐**：180M 像素/秒（VGA@30 只用掉 5%，4K@21fps 或 1080p@87fps）
- **4 核吞吐**：660M 像素/秒（4K@79fps，2K@178fps）
- **端到端延迟**：约 1 帧期——行缓冲 ~10 行 + 级间流水 ~30 拍 + 滞回 2~3 轮整帧遍历
- **SNN 推理**：64 步 × 5.56ns = 356ns@165MHz，每帧白送
- **功耗**（Vivado vectorless 估算）：0.277W，其中 MMCM 占动态的 69%

### 9.3 天花板分析（为什么停在这）

1. **BRAM 140 个**：每核滞回要 20 个 → 绝对上限 6 核（VGA 参数下）。
   2K 以上必须把帧图搬进 DDR（Zynq 的 PS 侧有 1GB DDR3）——那是
   下一个阶段的工程。
2. **布线拥塞**：4 核 80 个 BRAM 已让 180MHz 差 0.67ns。
3. **输入带宽**：DVP 8 位并口 ~56MHz。660M px/s 的处理能力需要
   MIPI 或多路并口才喂得饱——**当前瓶颈已在芯片外**。

## 10. 踩坑大全

每一条都是真实发生、真实浪费过时间的。按"你可能也会踩"排序。

1. **异步 FIFO 写地址差一**：`mem[wnext]` 写到了"下一个"地址，
   mem[0] 永远是 X。单模块测试全过、系统级全错——因为单模块从 mem[1]
   之后开始消费恰好对得上。**教训**：FIFO 要做"首字检查"——
   第一个写进去的字必须第一个读出来。
2. **2D 数组 + 组合遍历读 = LUT 灾难**：`mem[3][640]` 被综合器摊平成
   22908 LUT；改成 generate 每 bank 独立 1D 数组后只剩 127。
   **教训**：要分布式 RAM 就写成"单 bank 连续赋值读"的标准形状。
3. **BRAM 异步读推断不出来**：滞回位图早期是异步读，30 万 LUT 直接
   把综合器打到内存耗尽。**教训**：BRAM 只能同步读；想流水就
   "先出地址、下一拍用数据"地重构逻辑（本项目滞回因此整个改成
   地址早一拍、数据晚一拍的节奏）。
4. **`keep`/`dont_touch` 会引爆存储推断**：给滞回 BRAM 输出寄存器加
   keep 或 dont_touch 防优化，结果 Vivado 对上游 BRAM 的推断被扰动，
   4 核直接爆出 82k LUTRAM（超器件 4 倍）。**教训**：综合属性是
   双刃剑；动它之前留好回滚，动了立刻查资源报告。
5. **valid 与数据流水级数失配**：拆流水时 valid 链多了一级，
   输出全部错位一拍。**症状很有欺骗性**：只错 6%，集中在边界。
   **教训**：拆完流水画一张"级数对账表"——数据、valid、sof/eol/eof
   四条链每一级都数一遍。
6. **generate 引用了后面才声明的信号**：隐式推断成 1-bit wire，
   12 位阈值只剩 1 位，输出全 X。**教训**：信号声明放在 generate 之前；
   编译时开 `-sv` 严格模式能抓到部分此类问题。
7. **xsim 旧库污染**：改了 RTL 忘了重新 xvlog，或 xsim.dir 被僵尸进程
   锁住——跑的是旧网表，怎么改代码都"没反应"。**教训**：
   行为诡异时第一步 `rm -rf xsim.dir`（Windows 下先 taskkill xsimk.exe）。
8. **SCCB 从机在 SCL 高电平驱动 ACK 被误判为 START**：开漏总线协议
   时序细节。**教训**：行为级 I2C 从机模型要在 SCL 下降沿后才动作。
9. **引脚约束文件端口名与顶层不匹配**：xdc 里 `href`，顶层叫 `cam_href`，
   `get_ports` 静默返回空，70 个引脚全部没有位置约束——直到实现阶段
   才炸。**教训**：综合后立刻查 `report_utilization` 的 IO 数；
   约束文件当代码维护，改名要同步。
10. **TB 依赖固定延迟**：见 5.3。流水线一改 TB 全废。流式对比是唯一正解。

## 11. 词汇表

| 术语 | 一句话解释 |
|---|---|
| LUT | Look-Up Table，FPGA 的万能逻辑门，6 输入查表实现任意函数 |
| FF / 触发器 | Flip-Flop，时钟沿锁存 1 比特的最小存储单元 |
| BRAM | Block RAM，36Kb 固定块，双端口，适合大缓冲（行存/帧存）|
| 分布式 RAM | 用 LUT 拼的小 RAM，异步读，适合浅而宽的表 |
| CDC | Clock Domain Crossing，信号跨时钟域，必须用同步器或 FIFO |
| 亚稳态 | 触发器采样到变化中的数据后输出不定态，是 CDC 事故的根源 |
| 格雷码 | 相邻数只有 1 比特翻转的编码，异步指针的安全载体 |
| WNS / TNS | 最差/累计负时序裕量；WNS≥0 表示时序收敛 |
| 建立/保持时间 | 数据必须在时钟沿前/后稳定的最小时间 |
| 流水线 | 长组合路径中间插寄存器，用延迟换频率 |
| 转发/回压 | valid/ready 握手的一对方向：上游通知有数据/下游通知能收 |
| AXI-Stream | 单向流接口：tvalid/tdata/tlast(行尾)/tuser(帧头)|
| AXI4-Lite | 单拍读写的轻量配置总线（本项目寄存器堆用它）|
| 原语 | 厂商芯片里的硬电路单元（MMCME2_BASE/BUFG/RAMB36E1）|
| XDC | Vivado 约束文件：引脚位置、时钟定义、时序例外 |
| 综合Synthesis | Verilog → 门级网表 |
| 实现Implementation | 布局+布线（place & route）|
| OOC | Out-Of-Context，单模块独立综合，快速查资源/时序 |
| golden model | 软件参考模型，RTL 输出与它逐位对比 |
| 位精确 bit-exact | 每一位都相同（比"数值近似"严格得多）|

| NCHAN | 本项目的并行核数参数 |
| SOFT_CTRL | 1=用内置 FSM 代替 VexRiscv 软核（免网表依赖）|
